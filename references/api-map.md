# API Map

Use the exe-backed runtime at `http://127.0.0.1:8080`.

## API-key routes this skill uses

| Route | Auth | Purpose | CLI |
|---|---|---|---|
| `GET /v1/models` | API key | List available models | `models` |
| `POST /v1/images/generations` | API key | Synchronous text-to-image | `generate` |
| `POST /v1/images/edits` | API key | Synchronous reference edit | `edit` |
| `POST /v1/images/jobs` | API key | External async image task; text-to-image if no `input_images`, edit if `input_images` exists | `job submit`, `job run`, `batch mode=job` |
| `GET /v1/images/jobs/:id` | API key | Poll external async task and read asset metadata | `job wait`, `job run` |
| `/p/img/...` | signed URL | Download generated asset returned by a job | `asset save`, internal `job wait` save |

## Route roles

- `/v1/images/generations` and `/v1/images/edits` are OpenAI-compatible synchronous APIs.
- `/v1/images/jobs` is an API-key async task API for backup long jobs and polling. Do not use it as the default path when direct API is working.
- `/p/img/...` is a signed public asset download path generated by completed jobs.
- `batch` is a CLI orchestration layer. By default, rows with images call `/v1/images/edits` and rows without images call `/v1/images/generations`; `--concurrency` runs those direct API calls in parallel. Use `"mode": "job"` only when a row explicitly needs the backup async route.

## High-resolution note

The server accepts `gpt-image-2`, `gpt-image-2-2k`, and `gpt-image-2-4k` model IDs when available. `upscale=2k|4k` on async jobs is server-side post-processing; verify actual file dimensions with `info`.
